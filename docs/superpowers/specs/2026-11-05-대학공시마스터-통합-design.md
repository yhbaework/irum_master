# 대학공시 마스터 통합 설계

작성일: 2026-11-05

## 1. 무엇을, 왜

지금은 연 1회 하는 두 작업이 각자 다른 폴더의 스크립트로 나뉘어 있다.

| 작업 | 지금 스크립트 | 입력 | 만드는 것 |
|---|---|---|---|
| 학교마스터 | `학교마스터/build_UNIV_MASTER_M_BASE_당해연도.py` | 학과정보·학교개황 엑셀, `tcm1002m.csv` | `가공/UNIV_MASTER_M_BASE_<연도>.csv` |
| 지침서 | `정보공시지침서/build_tcm1004m_당해연도.py` | 대학정보공시 지침서 PDF | `가공/tcm1004m_<연도>.csv` |

이 둘을 **스크립트 하나**로 합친다. 쓰는 방식도 바꾼다. 해마다 **기본폴더를 복제해 연도 폴더를 만들고**,
그해 파일을 정해진 하위 폴더에 넣은 다음, **그 연도 폴더 안의 스크립트를 실행**하면 파일을 찾아
두 결과물을 그 폴더의 `EXPORT/`에 만든다. 상위 폴더에서 연도를 인자로 주고 실행하는 방식은 없앤다.

계산 내용(학과정보 병합, 학교개황 우선순위, 결측 보완, NOT NULL 점검, 지침서 추출 규칙)은 **바꾸지 않는다.**
바뀌는 것은 파일을 찾는 법, 실행 위치, 결과물 이름·위치, 실행 환경, 문서다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

목표
- 연도 폴더 하나에 파일을 넣고 스크립트 하나만 실행하면 두 결과물이 나온다.
- 5월: 두 작업 모두. 10월(선택): 학교마스터만 다시 만들고 지침서는 건너뛴다.
- 결과물 이름이 다른 작업의 결과물과 같은 규칙(`<테이블>_<만든날짜>_<연도>.csv`)을 따른다.

하지 않을 것
- 추출·보완 규칙 변경, DB 적재, 과거 연도(2021~2025) 재구축, 테스트 코드 작성.
- `tcm1001m.csv` 대조(참고용 겹침 개수 출력) — 기능을 뺀다.

실패로 보는 것 (돌아가더라도)
- 합친 스크립트로 2026년을 만든 결과가 기존 두 스크립트의 2026년 결과와 내용이 다르다.
- 10월에 다시 실행했을 때 5월에 손으로 고친 지침서 결과를 덮어쓰거나, 고치지 않은 새 지침서 결과가 옆에 생긴다.

## 3. 폴더 구조 (결정됨)

```
대학공시_DB 마스터/                                        ← 작업환경 (git 저장소 irum_master)
├─ setup.bat                                              ← 두 setup.bat을 합친 것
├─ requirements.txt                                       ← 이 작업에 필요한 것만
├─ irum_master/                                           ← 가상환경 (git 제외)
├─ 가이드.md
├─ 가이드_학교마스터.md
├─ 가이드_지침서.md
├─ (본 폴더를 복제한 다음 작업연도별 폴더를 생성하여 사용하세요)/   ← 기본폴더
│   ├─ <합친 스크립트>.py
│   ├─ 마스터_컬럼정의.csv                                  ← tcm1002m.csv 이름 변경
│   ├─ 정보공시지침서/      ← 지침서 PDF
│   ├─ 학과정보/            ← 학과정보_yyyyMMdd.xlsx|xls
│   ├─ 학교개황/            ← 학교개황_yyyyMMdd.xlsx|xls
│   └─ EXPORT/             ← 결과물
├─ 2026/                                                  ← 기본폴더를 복제한 연도 폴더
└─ 2027/ ...
```

- 기본폴더의 이름은 지금 저장소에 있는 그대로 쓴다.
- 하위 폴더 이름(`정보공시지침서`, `학과정보`, `학교개황`, `EXPORT`)은 고정이다.
- 가상환경은 작업환경 최상위에 하나만 두고 모든 연도 폴더가 함께 쓴다.

## 4. 실행 (결정됨)

```powershell
cd 2027
..\irum_master\Scripts\python.exe <합친 스크립트>.py
```

- 인자는 받지 않는다.
- 연도는 **연도 폴더 이름**(4자리 숫자)으로 정한다.

## 5. 파일 찾기 (결정됨)

| 종류 | 찾는 곳 | 규칙 |
|---|---|---|
| 지침서 | `정보공시지침서/` | 파일명에 `지침서`가 들어간 PDF가 정확히 1개 있어야 한다 (지금 규칙 유지) |
| 학과정보 | `학과정보/` | `.xlsx`, `.xls`. 1개 이상 있어야 한다 |
| 학교개황 | `학교개황/` | `.xlsx`, `.xls`. 1개 이상 있어야 한다 |
| 컬럼 정의 | 연도 폴더 바로 아래 | `마스터_컬럼정의.csv` (내용은 지금 `tcm1002m.csv`와 같고 이름만 바뀜) |

- 파일명에서 `기준`이 빠진다. 기준일자는 `<구분>_yyyyMMdd.<확장자>`의 8자리 숫자로 읽는다
  (예: `학교개황_20260722.xlsx`).
- 엑셀 임시파일(`~$`로 시작)은 무시한다 (지금 규칙 유지).

## 6. 결과물 (결정됨)

- 위치: 연도 폴더의 `EXPORT/`
- 이름:
  - `Univ_master_m_base_<만든날짜>_<연도>.csv`
  - `Tcm1004m_<만든날짜>_<연도>.csv`
- `<만든날짜>`는 실행한 날을 `yyMMdd`(6자리)로 쓴 것이다. 예: `Univ_master_m_base_261105_2026.csv`
  (원본 파일명의 기준일자는 지금처럼 8자리 `yyyyMMdd`로 읽는다. 바뀌는 것은 결과물 이름뿐이다.)
- 파일 내용(컬럼, 인코딩 UTF-8 BOM, 값 형식)은 지금과 같다.

## 7. 다시 실행할 때 (결정됨)

- 학교마스터: 실행할 때마다 그날 날짜로 새로 만든다. 이전 날짜 파일은 그대로 남는다.
- 지침서: `EXPORT/`에 그해 `Tcm1004m_*_<연도>.csv`가 **날짜와 상관없이 하나라도 있으면** 지침서 작업을
  건너뛰고 **건너뛰었다는 사실과 기존 파일명을 화면에 표시**한다. 손으로 고친 결과를 지키기 위해서다.
  다시 만들려면 기존 파일을 지우거나 `EXPORT/` 밖으로 옮긴다.
- 10월 재실행은 선택이다. 하지 않아도 된다.

## 8. 실행 환경 (결정됨)

- `setup.bat`: 두 파일을 하나로 합쳐 작업환경 최상위에 둔다. 가상환경 이름은 `irum_db` 대신 `irum_master`.
  안내 문구의 실행 예시도 이 작업 기준으로 바꾼다.
- `requirements.txt`: `pandas`, `openpyxl`, `xlrd`, `pdfplumber`만 둔다. `psycopg2-binary`는 뺀다.
- `.gitignore`에 `irum_master/`와 `EXPORT/`(모든 연도 폴더의 결과물)를 넣는다. 결과물은 git에 올리지 않는다.

## 9. 문서 (결정됨)

데이터를 어떻게 전처리해서 무엇을 만드는지 설명하는 문서로, 합친 작업 기준으로 다시 쓴다.

| 파일 | 내용 |
|---|---|
| `가이드.md` | 공통: 환경 준비(`setup.bat`, `irum_master`), 기본폴더 복제로 연도 폴더 만들기, 파일 넣는 곳과 파일명 규칙, 실행 명령, 결과물 이름, 5월/10월 실행, 폴더 구조 |
| `가이드_학교마스터.md` | 지금 `운영가이드.md`의 처리 흐름, 병합·결측 보완 규칙, 원본 형식이 바뀌었을 때, 결과 확인, 결과물 형식 |
| `가이드_지침서.md` | 지금 `tcm1004m_작업지침.md`의 추출 방식, 실행 결과 읽는 법, CSV 확인·수정, 멈췄을 때 |

- 지금 문서에서 빠지거나 바뀌는 내용: 연도 인자, `가공/`, `tcm1001m` 대조 줄, `tests/`를 쓰는 회귀 확인 절차,
  `build_tcm1004m_과거연도.py`·`작업기록_2021-2026.md`·`docs\...\2026-11-0x` 설계 문서 등 이 저장소에 없는 파일 언급.
- 스크립트의 오류 안내 문구 중 문서 이름을 가리키는 것(`tcm1004m_작업지침.md`)은 `가이드_지침서.md`로 바꾼다.

## 10. 검증

테스트 코드는 만들지 않는다 (사용자 결정). 대신 다음을 확인한다.

1. 기존 두 스크립트를 임시 폴더에서 2026년 파일로 실행한다. 학교마스터는 파일명에 ` 기준`이 있어야
   읽으므로 임시 폴더의 복사본 이름에만 붙인다. 원본 `2026/`은 건드리지 않는다.
2. 합친 스크립트로 `2026/`을 실행한다.
3. 두 결과를 이름만 다르고 내용이 같은지 비교한다.
4. 같은 날 한 번 더 실행해 지침서가 건너뛰어지고 그 사실이 표시되는지 본다.
5. 기본폴더에서 실행하면 연도를 알 수 없다며 멈추는지 본다.

## 11. 기존 파일 정리

- `2026/`과 기본폴더: `test.py`를 지우고 합친 스크립트를 넣는다. `tcm1002m.csv`는 `마스터_컬럼정의.csv`로 이름을 바꾼다.
  기본폴더의 비어 있는 하위 폴더(`정보공시지침서/`, `학과정보/`, `학교개황/`)는 git이 빈 폴더를 저장하지 않으므로
  `.gitkeep`을 넣는다. `EXPORT/`는 git에서 제외되므로 스크립트가 실행할 때 없으면 만든다.
- 통합이 끝나면 기존 `학교마스터/`, `정보공시지침서/` 폴더는 지운다 (git 기록에는 남는다).
  문서 내용은 9절의 가이드 3개로 옮긴 뒤에 지운다.

## 12. 빌더에게 맡긴 것 / 내가 정한 것

- 합친 스크립트의 파일명
- 실행 순서: 학교마스터 → 지침서. 지침서에서 멈춰도(형식 변경, PDF 없음 등) 이미 만든 학교마스터 결과는 남기고,
  마지막에 지침서가 실패했다고 표시한다. 학교마스터에서 멈추면 지침서는 진행하지 않는다.
- 연도 폴더 위치: 현재 작업 폴더가 아니라 **스크립트 파일이 있는 폴더**를 연도 폴더로 본다.
  다른 위치에서 실행하거나 더블클릭해도 같게 동작하게 하려는 것이다.
- 연도 폴더 이름이 4자리 숫자가 아니면(기본폴더에서 실행하면) 멈춘다.
- 연도 확인: 지금 하는 점검(학과정보 조사년도와 학교개황 파일명 연도, 지침서 파일명 연도)에 더해,
  모두 폴더 연도와 같아야 한다.
- 같은 날 학교마스터를 다시 실행하면 같은 이름의 파일을 덮어쓴다. 손으로 고치는 파일이 아니기 때문이다.
