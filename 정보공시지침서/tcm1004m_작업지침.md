# tcm1004m 지침서 정보 최신화 작업지침

이 문서는 이 작업을 **처음 하는 사람**을 위한 것이다. 순서대로 따라 하면 그해 지침서에서 공시항목별 공시시기·자료기준일을 뽑아 `tcm1004m` 적재용 CSV를 만들 수 있다.

## 1. 이 작업은 무엇인가

대학정보공시 데이터는 공시항목별 테이블(`UNIV_…`, `GRAD_…`)로 DB에 들어가 있다. 그런데 분석할 때 필요한 "이 항목은 **언제 공시**되고, 자료가 **어느 시점 기준**인가"는 DB에 없고, 매년 나오는 **대학정보공시 지침서(PDF)** 에만 있다.

이 작업은 지침서에서 대학·대학원 공시항목마다 다음 두 가지를 뽑아 `tcm1004m` 테이블에 그해 행으로 추가한다.

- **공시시기**: 지침서 각 항목의 【공시시기】 (예: `2026년 8월`)
- **자료기준일**: 지침서 각 항목의 【공시양식】에 적힌 자료기준일 (예: `2026. 4. 1.`)

각 컬럼의 뜻은 `tcm1004m_테이블정의서.xlsx`를 본다. 다음 항목은 넣지 않는다.
- PDF 파일로만 공시하는 항목 (항목명에 `[PDF]`가 붙은 학칙, 모집요강 등)
- 전문대학·대학원대학에만 해당하는 항목

## 2. 언제 하는가

- **매년 5월, 학교 마스터 작업 때 함께 한다.** 지침서는 1년에 한 번 공개되므로 1년에 한 번만 한다.
- 학교 마스터 작업은 10월에 한 번 더 할 수 있지만, **10월에는 이 작업을 하지 않는다.** 지침서가 바뀌지 않았기 때문이다.

## 3. 준비

1. **가상환경**: 프로젝트 폴더에 `irum_db` 폴더가 없으면 `setup.bat`을 실행한다. 가상환경을 만들고 `requirements.txt`의 패키지(PDF를 읽는 `pdfplumber` 포함)를 설치한다.
2. **연도 폴더 만들기**: 프로젝트 폴더 안에 그해 연도 이름의 폴더를 만든다. 예: `2027`
3. **지침서 PDF 넣기**: 그해 지침서를 연도 폴더 안에 넣는다. 바로 아래에 두어도 되고 하위 폴더에 두어도 된다.
   - 예: `2027\2027년 대학정보공시 지침서.pdf`, `2027\지침서\지침서_2027.pdf`
   - 파일명에 **`지침서`** 가 들어 있어야 한다.
   - 연도 폴더 안에 '지침서'가 들어간 PDF는 **하나만** 있어야 한다. 개정판을 받았으면 이전 파일은 빼 둔다.
   - 파일명에 연도가 있으면 그 연도를 쓰고, 없으면 연도 폴더 이름을 쓴다. 둘이 다르면 스크립트가 멈춘다.

## 4. 실행

PowerShell에서 프로젝트 폴더로 이동한 뒤 실행한다.

```powershell
$env:PYTHONIOENCODING = "utf-8"   # 콘솔에 한글이 깨지지 않게
irum_db\Scripts\python.exe build_tcm1004m_당해연도.py 2027
```

- 연도(`2027`)를 생략하면 프로젝트 안의 4자리 숫자 폴더 중 가장 최근 것을 쓴다.
- 결과는 `가공\tcm1004m_2027.csv` (UTF-8, BOM 포함)로 생긴다.
- 지침서 한 권을 읽는 데 몇 분 걸릴 수 있다. 마지막에 `완료`가 나오면 끝난 것이다.

## 5. 실행 결과 읽는 법

실행하면 아래 줄들이 차례로 나온다. 줄마다 뜻과 할 일을 적었다. 목록 형태의 줄(`…: N건`)은 0건이면 할 일이 없다.

| 출력 | 뜻 | 할 일 |
|---|---|---|
| `대상 폴더: 2027` / `[2027] 파일명` | 읽는 폴더와 지침서 | 맞는 파일인지 확인 |
| `읽은 쪽 338 / 블록 138개` | PDF 전체 쪽 수와, 찾은 항목 수. 여기서 '블록'은 지침서에서 `■ 공시지침`으로 시작하는 항목 하나를 말한다 | 해마다 130~140개 정도. 크게 줄었으면 형식이 바뀌었는지 의심 |
| `공시기관이 없어 건너뛴 '■ 공시지침' 구간: 쪽 [173]` | `■ 공시지침`은 있지만 【공시기관】이 없는 곳. 지침서 앞쪽 설명문이거나 원문 오타 | 그 쪽을 열어 공시항목이 아닌지 확인. 대개 무시해도 된다 |
| `행: 대학 106 / 대학원 18 / 제외 블록: 전문대학·대학원대학 전용 6, [PDF] 항목 17` | 만든 행 수와 뺀 항목 수 | 지난해 결과와 비슷한지 확인 |
| `! 경고: 공시시기에 가장 많은 연도는 …년인데 파일명은 …년입니다.` | 파일명의 연도가 틀렸을 수 있음 | 파일명·폴더명을 고치고 다시 실행 |
| `공시시기 빈 값: N건` | 【공시시기】가 비어 있는 항목 | 그 쪽을 열어 확인하고 CSV에서 직접 입력 |
| `자료기준일 빈 값(자체 양식 등): N건` | 지침서에 자료기준일이 없는 항목(학교 자체 양식, PDF 공시 등) | 정상이다. 할 일 없음 |
| `자료기준일을 '수시(…)' 괄호 안 값으로 채움: N건` | 수시로 공시하는 항목. 공시시기는 `수시`로, 공시 기준(예: 임원 현황 변동일로부터 30일 이내)은 자료기준일로 들어간다 | 정상이다. 할 일 없음 |
| `자료기준일 확인 필요(작성지침 참고) -> 해당 쪽 【작성지침】을 보고 CSV에서 직접 입력: N건` | 지침서에 "자료기준일은 작성지침 참고"라고만 적힌 항목. 스크립트는 날짜를 뽑지 않고 원문을 그대로 넣는다 | 출력된 쪽의 【작성지침】을 읽고 CSV의 자료기준일을 직접 고친다 |
| `연도를 채우지 못한 날짜(원문 확인 후 필요하면 CSV에서 직접 수정): N건` | 연도 없이 적힌 날짜(예: `1학기(4. 1.)`, `매년 4. 1.`) 중 연도를 확실히 알 수 없어 그대로 둔 것 | 원문을 보고 연도를 넣어야 하면 CSV에서 직접 고친다 |
| `참고: 변환 테이블명 중 tcm1001m.csv에 있는 이름(_M 제외 비교) N개 / N행` | 공시항목 목록(tcm1001m)과 테이블명이 몇 개 겹치는지. 참고용 | 할 일 없음. 항목번호가 바뀐 항목은 다르게 나오는 게 정상 |
| `-> 가공\tcm1004m_2027.csv (124행)` | 결과 파일 | 6장으로 |

스크립트가 자동으로 하는 정리도 알아 둔다. 원문과 다르게 보여도 정상이다.
- 날짜 표기를 `2026. 4. 1.` 형식으로 맞춘다 (`2026.4.1.` → `2026. 4. 1.`)
- 기간 기호를 `~` 하나로 맞춘다 (`～`, `∼` → `~`)
- `2026. 2월 말일`을 `2026. 2. 28.`로 바꾼다 (윤년이면 `29.`)
- `2025. 1. 1. ~ 12. 31.`처럼 바로 이어진 날짜의 빠진 연도를 채운다 (`~ 2025. 12. 31.`)
- `' : '`를 `': '`로, 여러 칸 공백을 한 칸으로 줄인다

## 6. 결과 CSV 확인과 수정

1. **원문과 대조**: `page_no`는 지침서 PDF의 쪽이다. PDF 뷰어에서 보이는 쪽 번호(첫 장이 1)이고, 지침서에 인쇄된 쪽번호와는 다르다. 뷰어의 쪽 이동에 이 번호를 넣으면 그 항목이 나온다. 5장의 목록에 나온 항목은 꼭 보고, 나머지는 몇 개 골라 본다.
2. **손으로 고칠 수 있는 것**: 스크립트가 고치지 못하는 것은 CSV에서 직접 고친다. 다른 곳(스크립트 등)에 적어 둘 필요는 없다.
   - 5장에서 "직접 입력/수정"이라고 한 항목
   - 지침서에서 줄이 바뀌던 자리에 끼어든 공백 (예: `30일 이내 에 공시` → `30일 이내에 공시`)
3. **엑셀로 열고 저장할 때**: 저장할 때 형식을 **CSV UTF-8(쉼표로 분리)** 로 유지한다. 다른 형식으로 저장하면 한글이 깨진다.
4. **다시 만들어야 할 때**: 결과 CSV가 이미 있으면 스크립트는 덮어쓰지 않고 `…가 이미 있습니다`라며 멈춘다. 손으로 고친 내용을 지키기 위해서다. 정말 다시 만들려면 기존 CSV를 지우거나 이름을 바꾼 뒤 실행한다. **이때 손으로 고친 내용은 새 파일에 없다.**

## 7. DB 적재

> 적재 방식(스크립트로 할지, 직접 할지)은 아직 정하지 않았다. 정해지면 이 장을 채운다.

- 적재할 때 `inpt_dt`(적재 일시, `YYYYMMDDHH24MISS`)를 채운다. CSV에서는 빈 칸이다.
- 키는 `disc_year` + `univ_grad_gbn` + `item_no`이다. 같은 연도를 다시 적재하면 키가 겹친다.

## 8. 스크립트가 멈췄을 때

### 스크립트가 지침서를 읽는 방식

지침서의 공시항목은 해마다 아래 모양으로 되어 있다. 스크립트는 이 모양을 기준으로 읽는다.

```
2-가-1. 전공과목 성적 분포                   ← 항목 제목 (번호 + 이름)
■ 공시지침                                    ← 항목 하나의 시작
【공시기관】: 대학 대학원 전문대학 대학원대학    ← 해당 기관만 파란 글씨
【공시시기】: 2026년 8월                       ← 공시시기
【공시양식】: 다음 양식 적용(자료기준일 : 2026. 4. 1.)   ← 자료기준일
■ 작성지침                                    ← 항목 설명 (여기부터는 읽지 않음)
```

1. PDF를 줄 단위로 읽는다. 쪽 오른쪽 끝에 있는 장 구분 탭의 글자는 버린다(본문 줄 끝에 붙어 들어오는 것을 막기 위해).
2. `■ 공시지침`마다 항목 하나로 나누고, 바로 위 줄에서 항목번호와 항목명을 찾는다.
3. 【공시기관】의 네 기관명 중 **파란 글씨**인 것이 해당 기관이다. 대학·대학원이 파란색이면 행을 만든다.
4. 【공시시기】와 【공시양식】 줄에서 값을 뽑는다. 괄호가 다음 줄로 넘어가면 이어 붙인다.
5. 모든 【공시기관】이 항목 하나가 되었는지 확인하고, 대학·대학원 행이 하나라도 있는지 확인한다. 하나라도 어긋나면 조용히 넘어가지 않고 멈춘다.

지침서 모양이 바뀌면 위 단계 중 하나에서 멈추고, 메시지 끝에 다음 안내가 붙는다.

> 지침서 형식이 변경되었다면 기존 스크립트로는 정보 추출이 불가능하며, 기존 작업지침(tcm1004m_작업지침.md)을 참고하여 스크립트 수정이 필요합니다.

**준비 문제** (안내 문구가 붙지 않는다. 스크립트를 고칠 필요 없음)

| 메시지 | 뜻 | 할 일 |
|---|---|---|

| `지침서 PDF가 여러 개입니다. 하나만 두세요` | 연도 폴더에 지침서 PDF가 2개 이상 | 하나만 남기기 |
| `파일명 연도(…)와 폴더 연도(…)가 다릅니다` / `연도를 알 수 없습니다` | 연도를 정할 수 없음 | 파일명이나 폴더명 고치기 |
| `… 지침서는 형식이 달라 이 스크립트로 처리하지 않습니다` | 2023년 이전 지침서 | 과거 연도는 다시 만들지 않는다 |
| `…가 이미 있습니다. 다시 만들려면 기존 파일을 지우거나 이름을 바꾸세요` | 결과 CSV가 이미 있음 | 6장 4번 |

**형식 변경** (안내 문구가 붙는다. 스크립트 수정이 필요할 수 있음)

| 메시지 | 원인으로 의심할 것 | 볼 곳 (스크립트의 이름) |
|---|---|---|
| `…쪽: 【공시시기】는 있는데 【공시기관】 줄을 찾지 못했습니다` | 【공시기관】 표기가 바뀌었거나, 앞에 다른 글자가 붙어 읽힘 | `블록_나누기`, `줄_읽기`(오른쪽 여백 `오른쪽_여백`) |
| `…쪽: 항목 제목을 읽지 못했습니다 - …` | 항목번호 모양이 바뀜 (예: `2-가-1)`처럼 기호가 바뀜), 제목이 세 줄 이상 | `항목번호_RE`, `항목제목_찾기` |
| `…쪽 …: 제목과 '■ 공시지침'이 다른 쪽에 있습니다` | 제목과 본문이 쪽을 넘어가며 갈라짐 | 원문 확인. 자주 나오면 `블록_나누기`의 쪽 검사 |
| `…쪽 …: 【공시시기】가 없습니다` | 【공시시기】 머리표 이름이 바뀜 | `블록_나누기` |
| `괄호가 닫히지 않습니다` / `괄호 짝이 맞지 않습니다` | 공시시기·공시양식의 괄호가 네 줄 이상 이어지거나 원문 괄호 오타 | `괄호_이어붙이기`(최대줄수), 원문 확인 |
| `…쪽: 【공시기관】에서 […]을(를) 찾지 못했습니다` | 기관 네 칸의 이름이 바뀜 | `기관명` |
| `…쪽: 【공시기관】 '…'의 글자색 …을(를) 판별할 수 없습니다` | 해당 기관 표시 색이 파란색이 아니게 바뀜 | `파란색`, `기관_판별_통합형` |
| `…쪽: 【공시기관】에 파란색 표시가 없습니다` | 색 대신 굵게·밑줄 등으로 표시 방식이 바뀜 | `기관_판별_통합형`, `줄_읽기`(글자 속성 읽기) |
| `… 대학 …가 두 번 나옵니다` | 같은 구분·같은 번호의 항목이 두 번 | 원문 확인 (번호 오타일 수 있음) |
| `블록이 되지 못한 【공시기관】이 있습니다 (쪽 …)` | 항목으로 나누지 못한 【공시기관】이 있음 | 그 쪽 원문, `블록_나누기` |
| `…: 대학 0행 / 대학원 0행 - 지침서 형식이 바뀌었는지 확인하세요` | 공시기관 표시 방식이 통째로 바뀜 | `기관_판별_통합형` |
| `항목번호 형식을 알 수 없습니다` | 테이블명으로 바꿀 수 없는 항목번호 | `테이블명_변환` |
| `'…'의 영문 표기가 없습니다 (…) -> 스크립트 상단 한글_영문에 추가하세요` | 항목번호에 처음 보는 한글(예: `커`)이 나옴. 형식 변경은 아니지만 안내 문구가 함께 나온다 | 스크립트 위쪽 `한글_영문`에 `"커": "KEO"`처럼 추가 (tcm1001m 테이블명 표기를 따른다) |
| 그 밖의 파이썬 오류 (Traceback) | 예상하지 못한 형식 | 오류가 난 함수부터 |

### 스크립트를 고친 뒤 확인

고친 결과가 이전 연도 지침서에서 달라지지 않는지 확인한다. **고치기 전에** 1번을 먼저 한다.

1. 고치기 전 스크립트로 이전 연도 결과를 임시 폴더에 만든다 (프로젝트의 `가공`에는 쓰지 않는다).

   ```powershell
   $env:PYTHONIOENCODING = "utf-8"
   $P = "C:\Users\…\대학공시_지침서"      # 프로젝트 폴더
   # 지난번 확인 때 만든 임시 폴더가 남아 있으면 옛 결과와 비교하게 되므로 먼저 지운다
   Remove-Item -Recurse -Force C:\temp\기준, C:\temp\이후 -ErrorAction SilentlyContinue
   mkdir C:\temp\기준; cd C:\temp\기준
   foreach ($y in 2024, 2025, 2026) { mkdir $y; Copy-Item "$P\지침서\${y}년*.pdf" $y }
   foreach ($y in 2024, 2025, 2026) { & "$P\irum_db\Scripts\python.exe" "$P\build_tcm1004m_당해연도.py" $y }
   ```

2. 스크립트를 고친다.
3. 테스트를 돌린다. 모두 `OK`여야 한다.

   ```powershell
   cd $P
   irum_db\Scripts\python.exe -m unittest tests.test_build_tcm1004m -v
   ```

4. 고친 스크립트로 다른 임시 폴더에 1번과 같이 다시 만든다 (1번 명령에서 `Remove-Item` 줄은 빼고, `기준`을 `이후`로 바꿔 실행).
5. 두 결과를 비교한다. 아무것도 출력되지 않으면 이전 연도 결과가 그대로라는 뜻이다.

   ```powershell
   foreach ($y in 2024, 2025, 2026) {
     Compare-Object (Get-Content -Encoding UTF8 "C:\temp\기준\가공\tcm1004m_$y.csv") (Get-Content -Encoding UTF8 "C:\temp\이후\가공\tcm1004m_$y.csv")
   }
   ```

6. 새 연도 지침서로 4장대로 실행한다.
